# Lane DASH — completion report

Read-only internal **run & cost dashboard**: LLM spend per stage / per day / per run, plus
run status. Branch `m5-dash`, DB `specula_wt_dash`.

## What I built

### API
- **`schemas/dashboard.py`** (new) — `CamelModel`-based `CostByStage`, `CostPoint`,
  `DashboardSummary`. Serializes to the frozen `@specula/shared-types` camelCase shapes.
  `recentRuns` reuses `schemas/run.py::RunOut` (imported read-only) so the `Run` shape —
  including the optional `cost` rollup — is produced by exactly one serializer.
- **`services/dashboard.py`** (new) — `compute_dashboard(session, user_id)`:
  - `totalCostUsd` = Σ `llm_costs.cost_usd` (summed as `Decimal`, cast to float at the
    boundary → no float-accumulation drift). Sums the **ledger**, not `runs.cost_usd`, because
    company ingest — the dominant spend — creates no `Run` (per the `LlmCost` docstring), so
    only `llm_costs` holds the full picture.
  - `runCount` = `len(runs)` — **derived server-side, never stored**.
  - `costByStage` = per-stage sum, ordered by spend desc then stage.
  - `costByDay` = `CostPoint[]` over the **union** of cost-days and run-days (a day with ingest
    spend but no run still appears, `runs: 0`); day bucketed by UTC date (`astimezone(UTC)`),
    independent of the DB session timezone.
  - `recentRuns` = newest-first, capped at `RECENT_RUN_LIMIT = 10`.
  - Every query filtered by `user_id` (belt-and-suspenders alongside RLS).
- **`routers/dashboard.py`** (filled the foundation stub) — `GET /dashboard` →
  `DashboardSummary` via `Depends(get_current_user_id)` + `Depends(get_session)`.

### Web (`/dashboard`, nav entry already registered)
- **`lib/api/dashboard.ts`** — `getDashboard()` → `bffFetch<DashboardSummary>("/dashboard")`.
- **`app/api/dashboard/route.ts`** — BFF GET passthrough.
- **`app/(app)/dashboard/page.tsx`** — server component rendering `DashboardView`.
- **`components/dashboard/dashboard-view.tsx`** — editorial-instrument view (matches the
  Insights panel/token system): total-spend + run-count tiles, spend-by-stage bars,
  spend-by-day bars, recent-runs table with status dots. Pure presentational server
  component; empty states for no spend / no runs.

  `llm_costs`/`runs` as-is.

  `recentRuns` follows automatically.
