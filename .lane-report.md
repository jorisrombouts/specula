# Lane LOAD — report

Load-test harness + expanded E2E for the M5 hardening flows. Branch `m5-load`, DB
`specula_wt_load`. **Merges LAST** (after NET → OBS → DATA → DASH).

## What I built (new files only — no shared surfaces touched)

### `load/` — k6 load harness (disjoint from all app code)
- `load/script.js` — drives the authed API the way the BFF does: an in-VM HS256 service JWT
  (`iss=specula-web`, `aud=specula-api`, `sub=demo-user`) in a Bearer header. Two scenarios:
  - `browse` (default): ramping VUs, 75% `GET /api/v1/jobs` + 25% `GET /api/v1/dashboard`,
    with think time. Per-endpoint p95 trends + a controlled `endpoint_errors` rate.
  - `ingest` (`-e INGEST=1`): a **metered** `POST /api/v1/runs` at ~1 trigger/10s. Records
    expected `429`s (past the NET cap) as `rate_limited_429`, deliberately NOT as errors.
  - Thresholds (fail the run if crossed): `endpoint_errors rate<0.01`, `jobs_latency p95<500`,
    `dashboard_latency p95<500`. A `setup()` warm-up fails loudly on a bad secret/down API.
- `load/README.md` — install, run, knobs, threshold meanings, and the recorded baseline.

### `apps/web/e2e/authed/` — new Playwright specs (inside the existing `authed` glob)
- `dashboard.spec.ts` — dashboard renders total spend + per-stage breakdown (DASH).
- `export.spec.ts` — `/settings` export downloads a JSON `ExportBundle`; asserts the shape
  and that global `skills_taxonomy` is excluded (DATA).
- `ratelimit.spec.ts` — a second run trigger inside the cooldown surfaces the `429` to the
  user (NET).
